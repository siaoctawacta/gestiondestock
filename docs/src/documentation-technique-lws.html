Chapitre 1

Objet du document et architecture

Ce document décrit pas à pas la mise en ligne de l'application de gestion de stock MM Cosmétiques sur l'hébergement mutualisé LWS, puis son exploitation au quotidien.

Les deux parties de l'application

PartieContenuAdresse
Application
frontend/		L'interface que les utilisateurs ouvrent dans leur navigateur (React). Une fois construite, ce n'est qu'un ensemble de fichiers statiques.https://stockpro.mmconsultingtg.com
API
backend/		Le serveur de l'application, écrit avec Laravel (PHP). Il gère la connexion des utilisateurs, vérifie les droits de chacun, enregistre ventes, stocks, transferts et déclarations dans la base MySQL, envoie les emails.https://stockpro.mmconsultingtg.com/api
Base de donnéesTables des boutiques, utilisateurs, produits, stocks, ventes, déclarations, journal d'audit.Base MySQL de l'hébergement LWS

Les deux parties sont livrées dans une seule archive et installées dans un seul dossier, servi par un seul sous-domaine : l'application compilée est placée dans le dossier public/ de Laravel, et le fichier public/.htaccess envoie les adresses /api/… à Laravel et toutes les autres à l'application. Tout tient dans l'offre d'hébergement mutualisé LWS, sans serveur dédié ni VPS.

Schéma de fonctionnement

Organisation sur le serveur

Sur LWS, chaque domaine et sous-domaine a son dossier dans htdocs/, qui en est la racine web. L'application occupe tout le dossier du sous-domaine :

/home/                                # « ~ » dans le terminal SSH
└── htdocs/
    ├── index.php  wp-admin/  …       # site WordPress de mmconsultingtg.com : ne pas toucher
    ├── mmcosmetiques.com/  …         # autres sites : ne pas toucher
    └── stockpro.mmconsultingtg.com/  # contenu de mm-stockpro.zip
        ├── .htaccess                 # renvoie toutes les requêtes vers public/
        ├── .env                      # configuration et mots de passe
        ├── app/  config/  database/  routes/  storage/  vendor/
        └── public/                   # seul dossier servi sur le web
            ├── index.html  assets/   # application React
            ├── index.php             # entrée de l'API Laravel (/api/…)
            ├── .htaccess             # /api → Laravel, le reste → application
            └── uploads/products/     # images des produits

Le .htaccess placé à la racine fait passer chaque adresse par public/ : le fichier .env, le code, vendor/ et storage/ ne sont jamais accessibles depuis Internet.

Pas de code source sur le serveur Ne déposez pas le code source GitHub (gestiondestock-main) sur l'hébergement : il ne fonctionne pas tel quel (rien n'y est compilé ni installé) et serait lisible par tout le monde. Seule l'archive mm-stockpro.zip (chapitre 3) est à téléverser.

Mode démo et mode production

L'application choisit son mode au moment de sa construction :

  • construite avec l'adresse du site (VITE_API_URL, ici https://stockpro.mmconsultingtg.com) : production, les données sont dans MySQL ;
  • construite sans adresse : mode démo, avec des données fictives stockées dans le navigateur et un bandeau jaune « Mode démo » en haut des pages.
À vérifier à chaque mise en ligne Si le site de production affiche le bandeau « Mode démo », il a été construit sans l'adresse de l'API : les ventes saisies resteraient dans le navigateur du poste et seraient perdues. Reconstruisez l'archive (chapitre 3) avant toute utilisation.
Le Laravel installé par l'installateur automatique LWS Il prouve que PHP fonctionne sur votre hébergement, mais ce n'est qu'un projet Laravel vide : il est remplacé par l'application. Sa base de données peut être réutilisée : ses identifiants figurent dans son fichier .env (chapitre 4). Elle occupe le dossier htdocs/stockpro.mmconsultingtg.com/ : le chapitre 5 explique comment la remplacer.
Chapitre 2

Prérequis

À réunir avant de commencer.

  • Une offre d'hébergement mutualisé LWS gérée avec LWS Panel (PHP 8.2 ou plus récent, base MySQL, Terminal SSH, Gestionnaire de fichiers).
  • Le sous-domaine stockpro.mmconsultingtg.com créé sur cet hébergement (son dossier htdocs/stockpro.mmconsultingtg.com/ existe).
  • Les accès à l'espace client LWS et à LWS Panel.
  • Un accès au dépôt GitHub siaoctawacta/gestiondestock (pour fabriquer les archives).
  • Une adresse email de l'hébergement pour l'envoi des emails, par exemple stockpro@mmconsultingtg.com.
  • Un gestionnaire de mots de passe pour conserver les mots de passe créés (base, email, Super Admin).

Chapitre 3

Préparer l'archive

Un seul fichier ZIP est à déposer sur l'hébergement : mm-stockpro.zip. Il contient tout le nécessaire ; aucun outil de développement n'est requis sur le serveur.

Contenu de l'archiveDétail
API LaravelCode, migrations de la base, dépendances incluses (dossier vendor/) : Composer n'est pas nécessaire sur le serveur. Pas de fichier .env : il se crée sur le serveur.
ApplicationCompilée pour https://stockpro.mmconsultingtg.com et placée dans public/.
public/.htaccessAiguillage : /api/… vers Laravel, le reste vers l'application ; HTTPS forcé ; fichiers sensibles bloqués.

3.1 Depuis GitHub (recommandé, rien à installer)

  1. Sur GitHub, ouvrez le dépôt puis l'onglet Actions.
  2. Dans la liste de gauche, choisissez Archive LWS, puis Run workflow.
  3. L'adresse proposée est déjà https://stockpro.mmconsultingtg.com : lancez.
  4. Après 2 à 3 minutes, ouvrez l'exécution terminée : en bas de page, section Artifacts, cliquez sur mm-stockpro.
  5. Le fichier téléchargé est mm-stockpro.zip : gardez-le tel quel, sans le décompresser sur votre ordinateur. C'est lui qui se charge sur le serveur au chapitre 5.

3.2 Depuis un ordinateur de développement

Avec PHP 8.2+, Composer, Node.js 20+ et zip installés :

git clone https://github.com/siaoctawacta/gestiondestock
cd gestiondestock
scripts/build-lws.sh https://stockpro.mmconsultingtg.com   # archive créée dans deploy/
Adresse du site L'adresse est inscrite dans l'application au moment de la construction. Si vous changez plus tard de sous-domaine, il faut refabriquer l'archive.
Chapitre 4

Configurer LWS Panel

Quatre réglages depuis LWS Panel : version de PHP, base de données, certificat SSL et boîte email. Les intitulés des rubriques peuvent varier légèrement selon la version du panneau.

4.1 Version de PHP

  1. Rubrique de configuration PHP du site : choisissez PHP 8.2 ou plus récent (8.3 conseillé) et vérifiez les extensions pdo_mysql, mbstring, openssl, xml, ctype, fileinfo, bcmath, intl, zip. Taille d'envoi maximale (upload_max_filesize, post_max_size) : 8 Mo au moins.
  2. Terminal SSH : le terminal a sa propre version de PHP. En haut de la page du terminal, cliquez sur le lien « Si vous souhaitez changer la version PHP du terminal par défaut, cliquez ici » et choisissez la même version.
  3. Dans le terminal, php -v doit afficher 8.2 ou plus.

4.2 Base de données MySQL

Réutiliser la base de l'installateur Laravel (le plus simple). Avant toute autre manipulation, ouvrez dans le Gestionnaire de fichiers htdocs/stockpro.mmconsultingtg.com/.env (le Laravel d'exemple) et notez ces quatre valeurs :

DB_HOST=…
DB_DATABASE=…
DB_USERNAME=…
DB_PASSWORD=…

Ou créer une nouvelle base dans la rubrique MySQL de LWS Panel, et noter le serveur MySQL, le nom de la base, l'utilisateur et le mot de passe indiqués.

Serveur MySQL Sur l'hébergement mutualisé, le serveur MySQL n'est pas forcément localhost : reprenez exactement la valeur DB_HOST indiquée par LWS.

4.3 Certificat SSL (HTTPS)

Rubrique SSL de LWS Panel : activez le certificat (Let's Encrypt) pour stockpro.mmconsultingtg.com. Le site redirige ensuite automatiquement vers HTTPS.

4.4 Boîte email d'envoi

Rubrique Emails de LWS Panel : créez une boîte, par exemple stockpro@mmconsultingtg.com (ou utilisez une boîte existante), et relevez son serveur SMTP (en général mail.mmconsultingtg.com, port 465, SSL). Elle envoie les emails « mot de passe oublié ».

Chapitre 5

Installer les fichiers

Le Laravel d'exemple de LWS est mis de côté et remplacé par l'archive, puis le fichier de configuration .env est créé.

5.1 Remplacer le Laravel d'exemple

Vérifiez d'abord que les identifiants de la base sont notés (4.2). Puis, dans le Terminal SSH :

cd ~/htdocs
mv stockpro.mmconsultingtg.com stockpro-ancien   # mise de côté, supprimée au chapitre 7

Dans le Gestionnaire de fichiers :

  1. Ouvrez htdocs, cliquez sur Charger et envoyez mm-stockpro.zip.
  2. Sélectionnez le fichier → Extraire : un dossier mm-stockpro apparaît dans htdocs.
  3. Renommez mm-stockpro en stockpro.mmconsultingtg.com (ou dans le terminal : cd ~/htdocs && mv mm-stockpro stockpro.mmconsultingtg.com).
  4. Supprimez mm-stockpro.zip.
  5. Vérifiez que htdocs/stockpro.mmconsultingtg.com/ contient .htaccess, .env.example, app/, public/, vendor/, et que public/ contient index.html, index.php et .htaccess.

5.2 Fichier de configuration .env

Dans le terminal :

cd ~/htdocs/stockpro.mmconsultingtg.com
cp .env.example .env

Ouvrez .env dans le Gestionnaire de fichiers (Modifier) et renseignez :

APP_ENV=production
APP_DEBUG=false
APP_URL=https://stockpro.mmconsultingtg.com
FRONTEND_URL=https://stockpro.mmconsultingtg.com

DB_CONNECTION=mysql
DB_HOST=valeur notée en 4.2
DB_PORT=3306
DB_DATABASE=valeur notée en 4.2
DB_USERNAME=valeur notée en 4.2
DB_PASSWORD=valeur notée en 4.2

MAIL_MAILER=smtp
MAIL_SCHEME=smtps
MAIL_HOST=mail.mmconsultingtg.com
MAIL_PORT=465
MAIL_USERNAME=stockpro@mmconsultingtg.com
MAIL_PASSWORD=le mot de passe de la boîte email
MAIL_FROM_ADDRESS=stockpro@mmconsultingtg.com
MAIL_FROM_NAME="MM Cosmétiques"
VariableRôle
APP_DEBUGToujours false en production : sinon une erreur afficherait la configuration, mots de passe compris.
APP_URLAdresse du site, sans / final (sert aussi à l'adresse des images produits).
FRONTEND_URLAdresse de l'application, ici identique à APP_URL : utilisée dans les liens « mot de passe oublié » et seule autorisée à appeler l'API.
TOKEN_DAYSDurée d'une connexion avant de devoir se reconnecter (30 jours par défaut).
APP_KEYLaissée vide : générée au chapitre 6.
Fuseau horaire L'API fonctionne en temps universel (UTC), identique à l'heure de Lomé toute l'année : les heures des ventes et des déclarations sont donc justes sans réglage.
Chapitre 6

Installer la base et le premier compte

Quelques commandes Laravel (artisan) créent les tables, les boutiques et le compte Super Admin.

6.1 Ouvrir un terminal

Dans l'espace client LWS, ouvrez la gestion du service de votre hébergement puis Terminal SSH. Vérifiez la version de PHP du terminal (4.1).

6.2 Commandes d'installation

cd ~/htdocs/stockpro.mmconsultingtg.com
php -v                               # doit afficher 8.2 ou plus
php artisan key:generate --force     # clé de chiffrement, UNE SEULE FOIS
php artisan migrate:fresh --force    # PREMIÈRE INSTALLATION SEULEMENT : vide la base, crée les tables
php artisan db:seed --force          # rôles, boutiques Agbalépédo et Cacaveli, catégories
php artisan mm:create-admin votre.email@mmconsultingtg.com --first=Prénom --last=Nom
php artisan optimize                 # met la configuration en cache
chmod -R 775 storage bootstrap/cache public/uploads

mm:create-admin demande le mot de passe du premier Super Admin (8 caractères minimum, non affiché à la saisie). Tous les autres comptes se créent ensuite depuis l'écran Utilisateurs de l'application.

migrate:fresh : uniquement à l'installation migrate:fresh supprime d'abord les tables d'exemple laissées par l'installateur LWS : certaines portent le même nom que celles de l'application (users…), et un simple migrate les garderait telles quelles. Cette commande efface toute la base : ne la relancez jamais une fois l'application en service. Pour les mises à jour, c'est php artisan migrate --force.
Version de PHP dans le terminal Si php -v affiche une version inférieure à 8.2, changez la version du terminal avec le lien en haut de la page du Terminal SSH (4.1), puis rouvrez le terminal.
La clé APP_KEY Ne relancez jamais key:generate sur une installation en service : toutes les connexions en cours seraient invalidées. Conservez une copie du fichier .env dans votre gestionnaire de mots de passe.

6.3 Catalogue de formation (facultatif)

Pour former le personnel sur le serveur avant le démarrage réel, la commande suivante ajoute 30 produits de démonstration et 50 unités de stock par boutique :

php artisan db:seed --class=DemoCatalogSeeder --force

À ne pas lancer sur une base contenant déjà le vrai catalogue. Pour repartir d'une base vierge après la formation : php artisan migrate:fresh --seed --force puis de nouveau mm:create-admin (efface toutes les données).

Chapitre 7

Mise en service

Liste de contrôle à dérouler avant d'ouvrir l'application au personnel.

  • https://stockpro.mmconsultingtg.com/api/health affiche {"status":"ok", …}.
  • https://stockpro.mmconsultingtg.com/.env ne s'affiche pas (erreur 403 ou 404).
  • https://stockpro.mmconsultingtg.com affiche l'écran de connexion sans bandeau « Mode démo », avec le cadenas HTTPS.
  • Connexion avec le Super Admin réussie ; actualiser une page (F5) sur /pos ne donne pas d'erreur 404.
  • Boutiques : adresses et téléphones d'Agbalépédo et de Cacaveli vérifiés.
  • Catalogue : un produit créé avec une image, l'image s'affiche.
  • Utilisateurs : comptes du personnel créés, chacun rattaché à sa boutique et à son rôle.
  • Mot de passe oublié testé depuis l'écran de connexion : l'email arrive, le lien ouvre stockpro.mmconsultingtg.com/reset-password.
  • Une vente test encaissée en caisse, visible dans l'historique et dans le stock, puis une déclaration du jour envoyée et validée.
  • Première sauvegarde de la base effectuée (chapitre 8).
  • Tout fonctionne : supprimez l'ancienne installation avec cd ~/htdocs && rm -rf stockpro-ancien.
Chapitre 8

Exploitation courante

Mettre à jour l'application, sauvegarder, consulter les journaux.

8.1 Mettre à jour l'application

  1. Récupérez une nouvelle archive (chapitre 3) et sauvegardez la base (8.2).
  2. Dans htdocs, renommez stockpro.mmconsultingtg.com en stockpro-ancien, chargez et extrayez le nouveau mm-stockpro.zip, puis renommez mm-stockpro en stockpro.mmconsultingtg.com.
  3. Recopiez depuis stockpro-ancien le fichier .env et le dossier public/uploads.
  4. Dans le terminal : 
    cd ~/htdocs/stockpro.mmconsultingtg.com
php artisan migrate --force          # jamais migrate:fresh ici
php artisan optimize
chmod -R 775 storage bootstrap/cache public/uploads
  5. Vérifiez l'application, puis supprimez stockpro-ancien.

Pendant l'opération, php artisan down met l'API en maintenance ; php artisan up rouvre l'accès.

8.2 Sauvegardes

QuoiComment
Base de donnéesphpMyAdmin (rubrique MySQL de LWS Panel) → base de l'application → Exporter. Au moins une fois par semaine.
Images produitsDossier public/uploads : Gestionnaire de fichiers → Archiver, puis Télécharger.
ConfigurationFichier .env, dans le gestionnaire de mots de passe.
Copie hors de l'hébergement Conservez les sauvegardes sur un autre support (ordinateur, stockage externe) : une sauvegarde restée sur l'hébergement disparaît avec lui. LWS propose aussi des sauvegardes de l'hébergement dans l'espace client : vérifiez leur fréquence.

Restaurer : phpMyAdmin → base de l'application → Importer le fichier .sql.

8.3 Journaux

  • Erreurs de l'API : htdocs/stockpro.mmconsultingtg.com/storage/logs/laravel-AAAA-MM-JJ.log (un fichier par jour, 14 jours conservés).
  • Actions des utilisateurs (créations, modifications, remises, validations) : écran Journal d'audit de l'application, réservé au Super Admin.

Chapitre 9

Sécurité

Ce que l'application garantit, et ce qui reste à votre charge.

Garanties de l'application

  • Chaque requête est contrôlée par l'API : connexion valide, compte actif, droit du rôle et boutique de l'utilisateur. Un caissier ou un responsable ne voit et ne modifie que sa boutique.
  • Totaux de vente recalculés par le serveur à partir du catalogue ; une remise supérieure à 15 % exige le mot de passe d'un responsable.
  • Stock jamais négatif (verrouillage des lignes pendant chaque vente ou transfert), transferts atomiques.
  • Mouvements de stock et journal d'audit non modifiables.
  • Seul le Super Admin crée, modifie ou supprime boutiques et comptes ; les suppressions sont logiques (l'historique est conservé).
  • Mots de passe chiffrés (bcrypt), 10 tentatives de connexion par minute au maximum, API accessible uniquement depuis l'adresse de l'application.

À votre charge

  • APP_DEBUG=false, .htaccess présent à la racine du dossier du sous-domaine, aucun code source déposé sur le serveur.
  • HTTPS actif sur stockpro.mmconsultingtg.com.
  • Mots de passe forts et différents pour l'espace client LWS, la base, l'email et le Super Admin ; double authentification activée sur l'espace client LWS.
  • Un compte nominatif par personne : jamais de compte partagé en caisse.
  • Désactivation immédiate du compte d'un employé qui quitte l'entreprise (écran Utilisateurs).
  • Sauvegardes testées : restaurez une sauvegarde sur une base de test au moins une fois.
  • Mises à jour de l'application appliquées (chapitre 8).
