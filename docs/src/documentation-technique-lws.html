Chapitre 1

Objet du document et architecture

Ce document décrit pas à pas la mise en ligne de l'application de gestion de stock MM Cosmétiques sur l'hébergement web cPanel de LWS, puis son exploitation au quotidien.

Les deux parties de l'application

PartieContenuAdresse
Application
frontend/		L'interface que les utilisateurs ouvrent dans leur navigateur (React). Une fois construite, ce n'est qu'un ensemble de fichiers statiques.https://stockpro.mmconsultingtg.com
API
backend/		Le serveur de l'application, écrit avec Laravel (PHP). Il gère la connexion des utilisateurs, vérifie les droits de chacun, enregistre ventes, stocks, transferts et déclarations dans la base MySQL, envoie les emails.https://stockpro.mmconsultingtg.com/api
Base de donnéesTables des boutiques, utilisateurs, produits, stocks, ventes, déclarations, journal d'audit.MySQL / MariaDB de cPanel (localhost)

Les deux parties sont livrées dans une seule archive et installées dans un seul dossier, servi par un seul sous-domaine : l'application compilée est placée dans le dossier public/ de Laravel, et le fichier public/.htaccess envoie les adresses /api/… à Laravel et toutes les autres à l'application. Tout tient dans une offre d'hébergement web cPanel, sans serveur dédié ni VPS.

Schéma de fonctionnement

Organisation sur le serveur

/home/cpaneluser/
├── mm-stockpro/            # application complète (hors de public_html)
│   ├── .env                # configuration et mots de passe : jamais accessible depuis le web
│   ├── app/  config/  database/  routes/  vendor/
│   ├── storage/logs/       # journaux d'erreurs
│   └── public/             # SEUL dossier exposé : racine de stockpro.mmconsultingtg.com
│       ├── index.html  assets/       # application React
│       ├── index.php               # entrée de l'API Laravel
│       ├── .htaccess               # /api → Laravel, le reste → application
│       └── uploads/products/       # images des produits
└── public_html/            # site principal, non concerné

Mode démo et mode production

L'application choisit son mode au moment de sa construction :

  • construite avec l'adresse du site (VITE_API_URL, ici https://stockpro.mmconsultingtg.com) : production, les données sont dans MySQL ;
  • construite sans adresse : mode démo, avec des données fictives stockées dans le navigateur et un bandeau jaune « Mode démo » en haut des pages.
À vérifier à chaque mise en ligne Si le site de production affiche le bandeau « Mode démo », il a été construit sans l'adresse de l'API : les ventes saisies resteraient dans le navigateur du poste et seraient perdues. Reconstruisez l'archive (chapitre 3) avant toute utilisation.
Le Laravel installé par l'installateur automatique LWS Il prouve que PHP fonctionne sur votre hébergement, mais ce n'est qu'un projet Laravel vide : il est remplacé par l'API de ce dépôt. S'il a créé une base de données, vous pouvez la réutiliser (ses identifiants figurent dans son fichier .env). Sinon, supprimez cette installation depuis l'installateur pour éviter toute confusion — en particulier si elle occupe déjà le sous-domaine stockpro.
Chapitre 2

Prérequis

À réunir avant de commencer.

  • Une offre d'hébergement web LWS avec cPanel (PHP 8.2 ou plus récent disponible, bases MySQL, accès SSH ou Terminal).
  • Le domaine mmconsultingtg.com rattaché à cet hébergement, pour créer le sous-domaine stockpro.
  • Les accès à l'espace client LWS et à cPanel.
  • Un accès au dépôt GitHub siaoctawacta/gestiondestock (pour fabriquer les archives).
  • Une adresse email de l'hébergement pour l'envoi des emails, par exemple stockpro@mmconsultingtg.com.
  • Un gestionnaire de mots de passe pour conserver les mots de passe créés (base, email, Super Admin).

Chapitre 3

Préparer l'archive

Un seul fichier ZIP est à déposer sur l'hébergement : mm-stockpro.zip. Il contient tout le nécessaire ; aucun outil de développement n'est requis sur le serveur.

Contenu de l'archiveDétail
API LaravelCode, migrations de la base, dépendances incluses (dossier vendor/) : Composer n'est pas nécessaire sur le serveur. Pas de fichier .env : il se crée sur le serveur.
ApplicationCompilée pour https://stockpro.mmconsultingtg.com et placée dans public/.
public/.htaccessAiguillage : /api/… vers Laravel, le reste vers l'application ; HTTPS forcé ; fichiers sensibles bloqués.

3.1 Depuis GitHub (recommandé, rien à installer)

  1. Sur GitHub, ouvrez le dépôt puis l'onglet Actions.
  2. Dans la liste de gauche, choisissez Archives LWS, puis Run workflow.
  3. L'adresse proposée est déjà https://stockpro.mmconsultingtg.com : lancez.
  4. Après 2 à 3 minutes, ouvrez l'exécution terminée : en bas de page, section Artifacts, téléchargez mm-stockpro.
  5. GitHub livre le fichier dans un ZIP : décompressez-le une fois sur votre ordinateur pour obtenir mm-stockpro.zip.

3.2 Depuis un ordinateur de développement

Avec PHP 8.2+, Composer, Node.js 20+ et zip installés :

git clone https://github.com/siaoctawacta/gestiondestock
cd gestiondestock
scripts/build-lws.sh https://stockpro.mmconsultingtg.com   # archive créée dans deploy/
Adresse du site L'adresse est inscrite dans l'application au moment de la construction. Si vous changez plus tard de sous-domaine, il faut refabriquer l'archive.
Chapitre 4

Configurer cPanel

Cinq réglages, tous depuis cPanel : version de PHP, base de données, sous-domaine, certificat SSL et boîte email.

4.1 Version de PHP

  1. cPanel → Sélectionner une version de PHP (Select PHP Version).
  2. Choisissez 8.2 ou plus récente (8.3 conseillé) puis Définir comme actuelle.
  3. Vérifiez que les extensions du chapitre 2 sont cochées (la plupart le sont déjà).
  4. Onglet Options : upload_max_filesize et post_max_size à 8M au moins, memory_limit à 256M.

4.2 Base de données MySQL

  1. cPanel → Bases de données MySQL.
  2. Créer une base : saisissez mmstock. cPanel ajoute votre identifiant devant : cpaneluser_mmstock.
  3. Ajouter un utilisateur : mmstock, avec un mot de passe fort (bouton Générateur de mot de passe). Nom final : cpaneluser_mmstock. Notez le mot de passe.
  4. Ajouter l'utilisateur à la base : choisissez l'utilisateur et la base, puis cochez TOUS LES PRIVILÈGES.
Rien à importer Les tables sont créées automatiquement par Laravel au chapitre 6. N'importez aucun fichier dans phpMyAdmin.

4.3 Sous-domaine

cPanel → Domaines (ou Sous-domaines selon la version) → Créer un nouveau domaine :

Sous-domaineRacine du document (Document Root)
stockpro.mmconsultingtg.commm-stockpro/public

Si le sous-domaine existe déjà (par exemple créé par l'installateur Laravel), modifiez sa racine dans Domaines (icône crayon).

Racine du sous-domaine La racine doit être le dossier public, et non mm-stockpro lui-même : sinon le fichier .env, qui contient les mots de passe, serait téléchargeable depuis Internet.

Si cPanel refuse une racine située hors de public_html, gardez la racine qu'il propose (par exemple public_html/stockpro), puis, une fois les fichiers en place (chapitre 5), remplacez ce dossier par un lien vers mm-stockpro/public depuis le terminal :

rm -rf ~/public_html/stockpro && ln -s ~/mm-stockpro/public ~/public_html/stockpro

4.4 Certificat SSL (HTTPS)

cPanel → SSL/TLS Status (ou Let's Encrypt SSL) : sélectionnez stockpro.mmconsultingtg.com et lancez l'émission du certificat. Comptez quelques minutes après la création du sous-domaine, le temps que le DNS se propage. Le site redirige ensuite automatiquement vers HTTPS.

4.5 Boîte email d'envoi

  1. cPanel → Comptes de messagerie → créez par exemple stockpro@mmconsultingtg.com (ou utilisez une boîte existante).
  2. Sur la ligne de la boîte, Connect Devices : relevez le serveur sortant (SMTP), en général mail.mmconsultingtg.com, port 465 (SSL).

Cette boîte envoie les emails « mot de passe oublié ».

Chapitre 5

Téléverser et configurer l'API

Dépôt de l'archive avec le Gestionnaire de fichiers, puis création du fichier de configuration .env.

5.1 Téléverser les fichiers

  1. cPanel → Gestionnaire de fichiers. En haut à droite, Paramètres → cochez Afficher les fichiers cachés (pour voir .env et .htaccess).
  2. Placez-vous dans votre dossier personnel (/home/cpaneluser, au-dessus de public_html). Téléverser → mm-stockpro.zip.
  3. Clic droit sur mm-stockpro.zip → Extract → dossier /home/cpaneluser. Vous obtenez mm-stockpro/ avec app/, public/, vendor/… Supprimez ensuite le ZIP.
  4. Vérifiez que mm-stockpro/public/ contient index.html, index.php, assets/ et .htaccess.

5.2 Fichier de configuration .env

Dans mm-stockpro/, clic droit sur .env.example → Copy → nommez la copie .env. Puis clic droit sur .env → Edit, et renseignez :

APP_ENV=production
APP_DEBUG=false
APP_URL=https://stockpro.mmconsultingtg.com
FRONTEND_URL=https://stockpro.mmconsultingtg.com

DB_CONNECTION=mysql
DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=cpaneluser_mmstock
DB_USERNAME=cpaneluser_mmstock
DB_PASSWORD=le mot de passe de l'étape 4.2

MAIL_MAILER=smtp
MAIL_SCHEME=smtps
MAIL_HOST=mail.mmconsultingtg.com
MAIL_PORT=465
MAIL_USERNAME=stockpro@mmconsultingtg.com
MAIL_PASSWORD=le mot de passe de la boîte email
MAIL_FROM_ADDRESS=stockpro@mmconsultingtg.com
MAIL_FROM_NAME="MM Cosmétiques"
VariableRôle
APP_DEBUGToujours false en production : sinon une erreur afficherait la configuration, mots de passe compris.
APP_URLAdresse du site, sans / final (sert aussi à l'adresse des images produits).
FRONTEND_URLAdresse de l'application, ici identique à APP_URL : utilisée dans les liens « mot de passe oublié » et seule autorisée à appeler l'API.
TOKEN_DAYSDurée d'une connexion avant de devoir se reconnecter (30 jours par défaut).
APP_KEYLaissée vide : générée au chapitre 6.
Fuseau horaire L'API fonctionne en temps universel (UTC), identique à l'heure de Lomé toute l'année : les heures des ventes et des déclarations sont donc justes sans réglage.
Chapitre 6

Installer la base et le premier compte

Quelques commandes Laravel (artisan) créent les tables, les boutiques et le compte Super Admin.

6.1 Ouvrir un terminal

Dans l'espace client LWS, ouvrez la gestion du service de votre hébergement puis Terminal SSH. À défaut : cPanel → Terminal, ou un client SSH (PuTTY, Terminal) avec les identifiants SSH fournis par LWS.

6.2 Commandes d'installation

cd ~/mm-stockpro
php -v                               # doit afficher 8.2 ou plus
php artisan key:generate --force     # clé de chiffrement, UNE SEULE FOIS
php artisan migrate --force          # crée toutes les tables
php artisan db:seed --force          # rôles, boutiques Agbalépédo et Cacaveli, catégories
php artisan mm:create-admin votre.email@mmconsultingtg.com --first=Prénom --last=Nom
php artisan optimize                 # met la configuration en cache
chmod -R 775 storage bootstrap/cache public/uploads

mm:create-admin demande le mot de passe du premier Super Admin (8 caractères minimum, non affiché à la saisie). Tous les autres comptes se créent ensuite depuis l'écran Utilisateurs de l'application.

Version de PHP dans le terminal Le terminal peut utiliser une autre version de PHP que celle choisie dans cPanel. Si php -v affiche une version inférieure à 8.2, utilisez le chemin complet, par exemple /opt/alt/php83/usr/bin/php artisan … (ou /opt/cpanel/ea-php83/root/usr/bin/php selon le serveur).
La clé APP_KEY Ne relancez jamais key:generate sur une installation en service : toutes les connexions en cours seraient invalidées. Conservez une copie du fichier .env dans votre gestionnaire de mots de passe.

6.3 Catalogue de formation (facultatif)

Pour former le personnel sur le serveur avant le démarrage réel, la commande suivante ajoute 30 produits de démonstration et 50 unités de stock par boutique :

php artisan db:seed --class=DemoCatalogSeeder --force

À ne pas lancer sur une base contenant déjà le vrai catalogue. Pour repartir d'une base vierge après la formation : php artisan migrate:fresh --seed --force puis de nouveau mm:create-admin (efface toutes les données).

Chapitre 7

Mise en service

Liste de contrôle à dérouler avant d'ouvrir l'application au personnel.

  • https://stockpro.mmconsultingtg.com/api/health affiche {"status":"ok", …}.
  • https://stockpro.mmconsultingtg.com/.env ne s'affiche pas (erreur 403 ou 404).
  • https://stockpro.mmconsultingtg.com affiche l'écran de connexion sans bandeau « Mode démo », avec le cadenas HTTPS.
  • Connexion avec le Super Admin réussie ; actualiser une page (F5) sur /pos ne donne pas d'erreur 404.
  • Boutiques : adresses et téléphones d'Agbalépédo et de Cacaveli vérifiés.
  • Catalogue : un produit créé avec une image, l'image s'affiche.
  • Utilisateurs : comptes du personnel créés, chacun rattaché à sa boutique et à son rôle.
  • Mot de passe oublié testé depuis l'écran de connexion : l'email arrive, le lien ouvre stockpro.mmconsultingtg.com/reset-password.
  • Une vente test encaissée en caisse, visible dans l'historique et dans le stock, puis une déclaration du jour envoyée et validée.
  • Première sauvegarde de la base effectuée (chapitre 8).
Chapitre 8

Exploitation courante

Mettre à jour l'application, sauvegarder, consulter les journaux.

8.1 Mettre à jour l'application

  1. Fabriquez de nouvelles archives (chapitre 3).
  2. Sauvegardez la base (8.2).
  3. Dans le Gestionnaire de fichiers, renommez mm-stockpro en mm-stockpro-ancien, puis extrayez le nouveau mm-stockpro.zip.
  4. Recopiez dans le nouveau mm-stockpro/ le fichier .env et le dossier public/uploads de mm-stockpro-ancien.
  5. Dans le terminal : 
    cd ~/mm-stockpro
php artisan migrate --force
php artisan optimize
chmod -R 775 storage bootstrap/cache public/uploads
  6. Vérifiez l'application, puis supprimez mm-stockpro-ancien.

Pendant l'opération, php artisan down affiche un message de maintenance ; php artisan up rouvre l'accès.

8.2 Sauvegardes

QuoiComment
Base (manuel)cPanel → Sauvegarde → Télécharger une sauvegarde de base de données MySQL, ou phpMyAdmin → Exporter.
Base (automatique)Voir la tâche Cron ci-dessous.
Images produitsDossier mm-stockpro/public/uploads : Gestionnaire de fichiers → Compress, puis téléchargement.
ConfigurationFichier mm-stockpro/.env, dans le gestionnaire de mots de passe.

Sauvegarde automatique chaque nuit : créez le dossier ~/sauvegardes, puis cPanel → Tâches Cron, réglage « une fois par jour », commande :

mysqldump --no-tablespaces -u cpaneluser_mmstock -p'MOTDEPASSE' cpaneluser_mmstock | gzip > ~/sauvegardes/mm-$(date +\%F).sql.gz && find ~/sauvegardes -name 'mm-*.sql.gz' -mtime +14 -delete
Copie hors de l'hébergement Téléchargez régulièrement (au moins chaque semaine) une sauvegarde sur un autre support : une sauvegarde restée sur l'hébergement disparaît avec lui.

Restaurer : phpMyAdmin → base cpaneluser_mmstock → Importer le fichier .sql (décompressé).

8.3 Journaux

  • Erreurs de l'API : mm-stockpro/storage/logs/laravel-AAAA-MM-JJ.log (un fichier par jour, 14 jours conservés).
  • Actions des utilisateurs (créations, modifications, remises, validations) : écran Journal d'audit de l'application, réservé au Super Admin.

Chapitre 9

Sécurité

Ce que l'application garantit, et ce qui reste à votre charge.

Garanties de l'application

  • Chaque requête est contrôlée par l'API : connexion valide, compte actif, droit du rôle et boutique de l'utilisateur. Un caissier ou un responsable ne voit et ne modifie que sa boutique.
  • Totaux de vente recalculés par le serveur à partir du catalogue ; une remise supérieure à 15 % exige le mot de passe d'un responsable.
  • Stock jamais négatif (verrouillage des lignes pendant chaque vente ou transfert), transferts atomiques.
  • Mouvements de stock et journal d'audit non modifiables.
  • Seul le Super Admin crée, modifie ou supprime boutiques et comptes ; les suppressions sont logiques (l'historique est conservé).
  • Mots de passe chiffrés (bcrypt), 10 tentatives de connexion par minute au maximum, API accessible uniquement depuis l'adresse de l'application.

À votre charge

  • APP_DEBUG=false et racine du sous-domaine sur mm-stockpro/public.
  • HTTPS actif sur stockpro.mmconsultingtg.com.
  • Mots de passe forts et différents pour cPanel, la base, l'email et le Super Admin ; double authentification activée sur l'espace client LWS et sur cPanel si proposée.
  • Un compte nominatif par personne : jamais de compte partagé en caisse.
  • Désactivation immédiate du compte d'un employé qui quitte l'entreprise (écran Utilisateurs).
  • Sauvegardes testées : restaurez une sauvegarde sur une base de test au moins une fois.
  • Mises à jour de l'application appliquées (chapitre 8).
